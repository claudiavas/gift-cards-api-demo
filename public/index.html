🎁 Gift Cards API

A REST API that automates reward delivery: it generates Amazon gift cards, encrypts them with AES-256-GCM, delivers them by email and keeps an immutable audit trail. Any CRM or backoffice can trigger it — rewards for referrals, promotions, loyalty programs or anything else.

Node.js + Express Amazon Incentives API AES-256-GCM PostgreSQL SendGrid Docker + CI

How it works

A CRM detects that a customer earned a reward and calls the API with a unique rewardId. The API validates the contact against the CRM, generates the gift card, encrypts the code before it touches any storage, emails it to the recipient, and records every action in an audit log the developer cannot alter.

Try it — walk the pipeline

Press each step in order: each one opens a popup with the exact HTTP call and the server's live response.

🧪 Demo mode: the requests are real, but Amazon, the CRM and SendGrid are simulated — codes are fake and no actual email is sent.

Security decisions

The design starts from one premise: a gift card code is bearer money, so neither the database, nor the logs, nor the developer should ever see one.

🔐 Immediate encryption

The code is encrypted with AES-256-GCM the instant Amazon returns it. It is only decrypted in memory, right before composing the email, and the variable is nulled afterwards.

🧹 Log sanitization

A middleware intercepts everything headed to the logs and redacts gift card codes, AWS keys, API tokens and emails using regex patterns — covered by unit tests.

🔁 Idempotency

A unique creationRequestId plus a constraint on rewardId guarantee a scheduler retry can never generate (and pay for) two cards.

📋 Independent audit

The access log is immutable and the auditor role is read-only: the business can verify what happened to every code without trusting the developer.

🚦 Rate limiting

Limits per API key and IP, plus resend rules: at most 1 per hour, 3 per day and 5 in total per card.

🛡️ Amazon error handling

Error codes (F300 funds, F400 temporary…) map to different strategies: exponential-backoff retry, CRM alert, or controlled failure.
